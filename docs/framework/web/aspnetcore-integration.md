# ASP.NET Core Integration

Hardened integrates with ASP.NET Core through a thin bridge layer. Your Hardened routes, DI registrations, and filters run inside the standard ASP.NET Core pipeline, giving you access to the full ASP.NET Core ecosystem (Kestrel, middleware, CORS, authentication, etc.) while keeping Hardened's compile-time benefits.

**Packages:** `Hardened.Web.AspNetCore.Runtime` (the bridge itself), plus the
`Hardened.Web.SourceGenerator` and `Hardened.DependencyModules.SourceGenerator` analyzers.

The bridge is implemented entirely as runtime middleware — `UseHardened()` and the
`HttpContext` ⇄ `IExecutionContext` mapping live in `Hardened.Web.AspNetCore.Runtime`.
No ASP.NET-specific source generator is involved.

---

## Application.cs Pattern

Every Hardened web application starts with an `Application` class decorated with `[HardenedModule]` and the ASP.NET Core runtime module attribute.

### Minimal Application

```csharp
using Hardened.Shared.Runtime.Attributes;

[HardenedModule]
[AspNetCoreRuntime.Module]
public partial class Application { }
```

This is the complete `Application.cs` file. The source generator does the rest:

- Implements `IApplicationModule` with all DI registrations
- Generates a `CreateBuilder(string[] args)` static method
- Wires Hardened routing into the ASP.NET Core pipeline

!!! note
    The class must be `partial` so the source generator can extend it.

---

## Program.cs Pattern

The `Program.cs` file follows the standard ASP.NET Core minimal hosting pattern, with `UseHardened()` as the bridge:

```csharp
var builder = Application.CreateBuilder(args);
var app = builder.Build();

app.UseHardened();
app.Run();
```

### What Each Line Does

| Line | Purpose |
|---|---|
| `Application.CreateBuilder(args)` | Creates a `WebApplicationBuilder` and registers all Hardened services |
| `builder.Build()` | Builds the `WebApplication` with DI container |
| `app.UseHardened()` | Adds the Hardened request pipeline as ASP.NET Core middleware |
| `app.Run()` | Starts the Kestrel server |

---

## CreateBuilder

`Application.CreateBuilder(args)` is a static method generated by the source generator. It wraps `WebApplication.CreateBuilder(args)` and adds all Hardened services to the `IServiceCollection`.

You can configure the builder just like you would in any ASP.NET Core application:

```csharp
var builder = Application.CreateBuilder(args);

// Add ASP.NET Core services
builder.Services.AddCors(options => {
    options.AddPolicy("AllowAll", policy => {
        policy.AllowAnyOrigin()
              .AllowAnyMethod()
              .AllowAnyHeader();
    });
});

builder.Services.AddHealthChecks();

// Configure Kestrel
builder.WebHost.ConfigureKestrel(options => {
    options.ListenAnyIP(8080);
});

var app = builder.Build();
```

## UseHardened

`app.UseHardened()` registers the Hardened request pipeline as ASP.NET Core middleware. This is where Hardened's compile-time routing tree takes over request processing.

You can combine `UseHardened()` with other ASP.NET Core middleware:

```csharp
var builder = Application.CreateBuilder(args);
var app = builder.Build();

// ASP.NET Core middleware (runs before Hardened)
app.UseCors("AllowAll");
app.UseAuthentication();
app.UseAuthorization();

// Hardened pipeline
app.UseHardened();

// Fallback for unmatched routes
app.MapFallback(() => Results.NotFound());

app.Run();
```

!!! tip
    Middleware registered before `UseHardened()` runs before Hardened's filter pipeline. Middleware registered after `UseHardened()` only runs for requests that Hardened does not handle.

## Configuration with IAppConfig

Add a `ConfigureApplication` method to your `Application` class to configure Hardened services:

```csharp
[HardenedModule]
[AspNetCoreRuntime.Module]
public partial class Application {
    private static void ConfigureApplication(IAppConfig appConfig) {
        appConfig.Amend<DatabaseConfig>(config => {
            config.MaxPoolSize = 25;
        });

        appConfig.Amend<DatabaseConfig>(config => {
            config.MaxPoolSize = 100;
        }, environment: "Production");
    }
}
```

The source generator detects this method by convention and calls it during module configuration.

## Complete Example

Here is a complete Hardened web application with ASP.NET Core integration:

=== "Application.cs"

    ```csharp
    using Hardened.Shared.Runtime.Attributes;
    using Hardened.Shared.Runtime.Configuration;

    [HardenedModule]
    [AspNetCoreRuntime.Module]
    public partial class Application {
        private static void ConfigureApplication(IAppConfig appConfig) {
            appConfig.Amend<ApiConfig>(config => {
                config.RateLimit = 100;
            });
        }
    }
    ```

=== "Program.cs"

    ```csharp
    var builder = Application.CreateBuilder(args);

    builder.Services.AddCors(options => {
        options.AddDefaultPolicy(policy => {
            policy.AllowAnyOrigin()
                  .AllowAnyMethod()
                  .AllowAnyHeader();
        });
    });

    var app = builder.Build();

    app.UseCors();
    app.UseHardened();
    app.Run();
    ```

=== "ProductController.cs"

    ```csharp
    using Hardened.Web.Runtime.Attributes;

    [BasePath("/api")]
    public class ProductController {
        [Get("/products")]
        public Task<IReadOnlyList<Product>> List(
            IProductRepository repo) {
            return repo.GetAll();
        }

        [Get("/products/{id}")]
        public Task<Product?> GetById(
            string id,
            IProductRepository repo) {
            return repo.GetById(id);
        }

        [Post("/products")]
        public Task<Product> Create(
            CreateProductRequest request,
            IProductService service) {
            return service.Create(request);
        }
    }
    ```

=== "IProductRepository.cs"

    ```csharp
    using Hardened.Shared.Runtime.Attributes;

    public interface IProductRepository {
        Task<IReadOnlyList<Product>> GetAll();
        Task<Product?> GetById(string id);
    }

    [Expose(typeof(IProductRepository))]
    [Singleton]
    public class InMemoryProductRepository : IProductRepository {
        private readonly List<Product> _products = new();

        public Task<IReadOnlyList<Product>> GetAll()
            => Task.FromResult<IReadOnlyList<Product>>(_products);

        public Task<Product?> GetById(string id)
            => Task.FromResult(_products.FirstOrDefault(p => p.Id == id));
    }
    ```

## ASP.NET Core Features

Since Hardened runs inside ASP.NET Core, you have full access to the ASP.NET Core ecosystem:

### Health Checks

```csharp
var builder = Application.CreateBuilder(args);
builder.Services.AddHealthChecks()
    .AddCheck<DatabaseHealthCheck>("database");

var app = builder.Build();
app.MapHealthChecks("/health");
app.UseHardened();
app.Run();
```

### HTTPS and HSTS

```csharp
var app = builder.Build();
app.UseHttpsRedirection();
app.UseHsts();
app.UseHardened();
app.Run();
```

### Static Files

```csharp
var app = builder.Build();
app.UseStaticFiles();
app.UseHardened();
app.Run();
```

### Logging

ASP.NET Core logging is available through standard `ILogger<T>` injection, which works seamlessly with Hardened's DI:

```csharp
[Expose(typeof(IOrderService))]
public class OrderService : IOrderService {
    private readonly ILogger<OrderService> _logger;

    public OrderService(ILogger<OrderService> logger) {
        _logger = logger;
    }

    public async Task<Order> Create(CreateOrderRequest request) {
        _logger.LogInformation("Creating order for customer {CustomerId}",
            request.CustomerId);
        // ...
    }
}
```
